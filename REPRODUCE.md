## Quick start

```bash
# 1. Clone and enter the repo
git clone <repo-url>
cd Thesis

# 2. Install dependencies
pip install -e .[dev]

# 3. Start Ollama (if not already running)
ollama serve &
ollama pull phi3:mini
ollama pull llama3.1:8b

# 4. Run the full pipeline (approx. 30 hours on 24 GB Ryzen, no GPU)
bash replicate.sh

# — or — run a fast smoke check (~1 hour, 50 instances)
bash replicate.sh --quick
```

On completion you will find:

- `runs.jsonl` — raw experimental log (one JSON line per run)
- `RESULTS.md` — auto-generated analysis with tables and hypothesis tests
- `figures/` — five publication-ready figures (generated by Stage 6)

## Stage-by-stage explanation

### Stage 1 — Environment check

Verifies that all required software is present before wasting compute.

- Checks Python >= 3.11.
- Checks that `mas` is importable; if not, runs `pip install -e .[dev]`.
- Checks Ollama is installed and the server is reachable at `localhost:11434`.
- Checks that `phi3:mini` and `llama3.1:8b` are pulled; if not, calls
  `ollama pull` automatically.

**Fatal** when running experiments (not skipped with `--skip-experiments`
or `--dry-run`).

### Stage 2 — Pre-flight validation

Runs `python -m mas.eval.preflight` against the `goals/` directory.

Checks:
- Every goal file validates against `goals/_schema.json`.
- No placeholder (`_placeholder: true`) or TBD content.
- Goal-type counts match EXPERIMENTS.md §3: 91 adversarial + 32 code + 27 sequential (150 total).
- Adversarial corruption patterns: 19 drop_required_field + 18 each for the other four types.
- Rubric validity: every check has a valid `check_type`.

**Aborts** if any hard error is found. Fix the flagged goal files before
re-running.

### Stage 3 — Main experimental batch

```
python -m mas.eval.cli batch \
    --conditions FULL_FRAMEWORK,BASELINE_LANGGRAPH \
    --goal-types all \
    --instances  all \
    --resume
```

Runs 300 experiments: 2 conditions × 150 instances × seed 0.

Conditions:
- `FULL_FRAMEWORK` — System 0/3: System-0 enforcement + VoC-UCB routing.
- `BASELINE_LANGGRAPH` — vanilla LangGraph + Pydantic; no System-0 or routing.

Each run appends one JSON line to `runs.jsonl` and one checkpoint triple to
`runs_completed.txt`. Both files are append-only and locked via `fcntl` for
safe parallel writes.

**Resumability:** `--resume` skips triples already in `runs_completed.txt`,
so a crashed batch can be restarted without losing progress.

**Expected runtime:** ~18–25 hours (sequential, 24 GB Ryzen).  
Use `--parallel 2` to halve the wall-clock time at the cost of peak RAM.

### Stage 4 — Frontier replication (optional)

```
python -m mas.eval.cli batch \
    --conditions    FULL_FRAMEWORK \
    --backend       anthropic \
    --judge-backend anthropic \
    --instances     all \
    --resume
```

Reruns the 150 FULL_FRAMEWORK instances against Claude Sonnet (Anthropic API)
instead of the local llama3.1:8b.

**Skipped** when `ANTHROPIC_API_KEY` is not set. The script prints a warning
and continues without error.

**Cost:** approximately $50 USD (150 runs × ~4,000 tokens average × $3/MTok
input + $15/MTok output).

### Stage 5 — Robustness checks

```
python -m mas.eval.cli robustness all
```

Runs the four pre-specified robustness checks from EXPERIMENTS.md §7.5:

1. **Temperature sweep** — Re-run 50 random instances at temperature ∈ {0.0, 0.7}.
   Verifies that the CFR direction is preserved across temperatures.
2. **Seed sweep** — Re-run 50 random instances at seed and seed+1000.
   Verifies that results are not seed-specific.
3. **Drop-adversarial sensitivity** — Recompute primary tests excluding the
   `adversarial_reliability` goal type.
4. **Threshold sensitivity** — Re-run 50 random instances with
   τ_sys1 ∈ {0.5, 0.7, 0.9}.

Results are appended to `RESULTS.md`.

**Expected runtime:** ~8–10 hours.

### Stage 6 — Analysis

```
python -m mas.eval.cli logs validate
python -m mas.eval.cli logs dedupe --strategy successful
python -m mas.eval.cli results
python -m mas.eval.cli failures
```

1. **Validate** — stream-validates every line of `runs.jsonl` against the
   EXPERIMENTS.md §4 schema. Reports malformed lines.
2. **Dedupe** — atomically removes duplicate `(goal_id, condition, seed)`
   triples, keeping the successful run where one exists.
3. **Results** — runs all pre-specified statistical analyses (McNemar,
   Wilcoxon, bootstrap CIs) and writes `RESULTS.md`.
4. **Failures** — categorises every non-successful run into seven mutually
   exclusive failure modes and appends a section to `RESULTS.md`.

If `runs.jsonl` is empty or absent, Stage 6 prints a warning and exits
cleanly without error.

## Flag reference

| Flag | Effect |
|---|---|
| `--skip-experiments` | Skip Stages 1–5; go straight to Stage 6. |
| `--skip-robustness` | Skip Stage 5 only. |
| `--skip-frontier` | Skip Stage 4 only. |
| `--quick` | Limit Stage 3 to 50 runs (10/goal type, FULL_FRAMEWORK only). |
| `--dry-run` | List what would run without executing. Implies `--skip-frontier`. |

Flags may be combined:

```bash
bash replicate.sh --quick --skip-frontier      # local 50-run smoke, no API
bash replicate.sh --skip-experiments           # rebuild RESULTS.md from existing data
bash replicate.sh --skip-robustness            # full batch, skip ~8 h of sweeps
```

## Idempotency and resumability

`replicate.sh` is fully idempotent:

- The `--resume` flag (passed to all batch commands) checks
  `runs_completed.txt` before each run. Already-completed triples are
  skipped automatically.
- Re-running `replicate.sh` after an interruption will pick up exactly
  where it left off.
- Stage 6 (dedupe) is idempotent: running it twice on the same log
  produces the same result.

## Troubleshooting

### Ollama not running

```
[FAIL] Ollama not responding at localhost:11434 — start with: ollama serve
```

**Fix:** Start the Ollama daemon:

```bash
ollama serve &
```

Or, if you prefer a foreground process, open a second terminal and keep it
running there while replicate.sh executes.

### Model not found

```
[WARN] Model phi3:mini not found — pulling now ...
```

The script auto-pulls missing models. If the pull fails (network issue):

```bash
ollama pull phi3:mini
ollama pull llama3.1:8b
```

Then re-run `replicate.sh`; it will detect the models are now present.

### Pre-flight errors

```
[FAIL] Stage 2: pre-flight
PRE-FLIGHT FAILED (3 error(s)) — aborting batch.
  ✗ goal type 'research_synthesis': 28 instances (expected 30)
  ...
```

**Fix:** Author the missing goal instances in `goals/<type>/`. The error
messages identify exactly which types and strata are under-filled. After
fixing, re-run from Stage 2:

```bash
bash replicate.sh  # or: python -m mas.eval.preflight && bash replicate.sh
```

### Batch interrupted mid-run

A Ctrl-C or system crash produces an incomplete `runs.jsonl`. Simply re-run:

```bash
bash replicate.sh --resume
```

The `--resume` flag reads `runs_completed.txt` and skips any triples that
already completed successfully.

### ANTHROPIC_API_KEY not set

```
[WARN] ANTHROPIC_API_KEY not set — skipping frontier replication.
```

This is informational. Stage 4 is skipped without error. To include frontier
results:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
bash replicate.sh --skip-experiments  # if other stages already ran
```

### `pip install -e .[dev]` fails

```
[FAIL] pip install -e .[dev] failed — install dependencies manually.
```

Try manually:

```bash
pip install -r requirements.txt
pip install -e .
```

If specific packages fail, check `requirements.txt` for version constraints
and ensure you are using Python >= 3.11.

### Analysis produces empty RESULTS.md

If Stage 6 prints:

```
[WARN] No run data found in ./runs.jsonl — skipping results generation.
```

This means `runs.jsonl` is empty. Run the experiments first (Stage 3), or
point `MAS_RUNS_LOG` at an existing populated log:

```bash
MAS_RUNS_LOG=/path/to/existing/runs.jsonl bash replicate.sh --skip-experiments
```

## How to interpret RESULTS.md

`RESULTS.md` is auto-generated by `python -m mas.eval.cli results`. Do not
hand-edit it — regenerate instead.

### Key sections

**Condition summary table** — per-condition counts, success rate, CFR rate,
mean token usage. The comparison of interest is FULL_FRAMEWORK vs
BASELINE_LANGGRAPH.

**Primary hypothesis (H1)** — Three pre-registered paired tests at α = 0.05
(no Bonferroni correction): McNemar on cascade failure, McNemar on success, and
Wilcoxon on total tokens (FULL_FRAMEWORK vs BASELINE_LANGGRAPH). Reported with
Cohen's h (binary) or Cliff's δ (continuous) and 95% bootstrap CIs.

**Bootstrap CIs** — All effect sizes include 95% bootstrap CIs (n = 10,000
paired resamples).

**Robustness section** — Appended by Stage 5. Reports whether the CFR
direction is preserved under temperature/seed/threshold perturbations.

**Failure mode analysis** — Appended by Stage 6. Categorises every failed
run into seven mutually exclusive types (schema_validation_failure,
cascade_failure, timeout, etc.).

### Figures

Five figures are generated alongside `RESULTS.md`:

| Figure | File | Description |
|---|---|---|
| 1 | `figures/cascade_bar.png` | CFR by condition (bar chart) |
| 2 | `figures/cost_quality_pareto.png` | Token cost vs success rate (scatter) |
| 3 | `figures/per_step_survival.png` | Survival curve: steps before first S0 catch |
| 4 | `figures/voc_convergence.png` | VoC trace convergence across runs |
| 5 | `figures/frontier_vs_local.png` | CFR comparison: Anthropic vs Ollama backend |

If figures are not needed, pass `--no-figures` to the results command:

```bash
python -m mas.eval.cli results --no-figures
```

## Reproducing a single run

To reproduce one specific run outside the full pipeline:

```bash
python -m mas.eval.cli run \
    --condition FULL_FRAMEWORK \
    --goal-id   research_synth_001 \
    --seed      42
```

The output is appended to `./runs.jsonl` by default. Use `--no-write` to
print to stdout instead:

```bash
python -m mas.eval.cli run \
    --condition FULL_FRAMEWORK \
    --goal-id   research_synth_001 \
    --seed      42 \
    --no-write
```

## Verifying reproducibility

All seeds are fixed and logged in every RunLog entry (`seed` field in
EXPERIMENTS.md §4). To verify that a re-run produces bit-identical outputs:

1. Run the batch with a fixed seed (default: 0).
2. Compare `run_id` fields — they are UUID-v4 and will differ (random).
3. Compare `final_output`, `success`, `cascade_failure` — these should match
   given identical seed, model weights, and Ollama version.

Note: Ollama model quantisation and CPU inference are deterministic for a
fixed seed. GPU inference may introduce floating-point non-determinism.
